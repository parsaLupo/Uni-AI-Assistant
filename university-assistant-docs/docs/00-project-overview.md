# 00 — Project Overview

## 1. Problem statement

دانشجو معمولاً برای پاسخ به پرسش‌هایی مثل پیش‌نیاز درس، زمان امتحان، قوانین مشروطی، زمان انتخاب واحد و اطلاعات استاد باید بین چند سامانه، فایل PDF و اطلاعیه جستجو کند. هدف این پروژه ایجاد یک نقطه دسترسی واحد و قابل اعتماد برای این اطلاعات است.

## 2. Vision

ساخت یک دستیار دانشگاهی که پرسش دانشجو را به زبان طبیعی دریافت کند، نوع اطلاعات موردنیاز را تشخیص دهد، اطلاعات معتبر دانشگاه را بازیابی کند و پاسخ روشن، قابل پیگیری و ترجیحاً مستند ارائه دهد.

## 3. Users

### Student

- مشاهده اطلاعات دانشگاهی
- پرسش از دستیار
- مشاهده منابع پاسخ
- مشاهده تاریخچه مکالمات
- مشاهده درس/استاد/تقویم/امتحانات
- استفاده از ابزارهای انتخاب واحد در نسخه‌های بعدی

### Professor

در MVP نقش استاد حداقلی است و عمدتاً برای نگهداری اطلاعات دروس ارائه‌شده استفاده می‌شود. امکانات اختصاصی استاد در صورت نیاز در نسخه بعدی تعریف می‌شود.

### Admin

- مدیریت کاربران
- مدیریت داده‌های دانشگاه
- بارگذاری و نسخه‌بندی اسناد
- مدیریت اطلاعیه‌ها و تقویم
- مشاهده آمار و لاگ‌های مدیریتی

## 4. Key use cases

1. Student asks: «پیش‌نیاز ساختمان داده چیست؟»
2. Student asks: «امتحان ریاضی ۲ چه زمانی است؟»
3. Student asks: «شرایط مشروطی چیست؟»
4. Student searches for professors teaching a course in a term.
5. Student searches courses with specific properties.
6. Admin uploads a new academic regulation PDF.
7. Admin updates an exam schedule.
8. System answers with source information when the answer depends on official documents.

## 5. Success criteria

- پاسخ به پرسش‌های ساختاریافته با داده صحیح از PostgreSQL.
- پاسخ به پرسش‌های مبتنی بر اسناد با grounding و citation.
- عدم نمایش داده‌ای که کاربر مجوز دیدن آن را ندارد.
- امکان به‌روزرسانی داده‌ها بدون نیاز به تغییر کد.
- استقلال frontend از database/LLM provider.

## 6. Non-goals for MVP

- ساخت مدل زبانی از صفر
- اتصال مستقیم به سامانه دانشگاه بدون قرارداد/دسترسی رسمی
- اجرای خودکار انتخاب واحد واقعی به‌جای سامانه رسمی
- توصیه‌گر پیچیده مبتنی بر یادگیری ماشین
- اپلیکیشن موبایل native

## 7. Architectural principle

داده دانشگاهی ساختاریافته با query منطقی از PostgreSQL خوانده می‌شود؛ اطلاعات غیرساختاریافته از RAG استخراج می‌شود؛ و مدل زبانی وظیفه فهم سؤال، ترکیب context و تولید پاسخ طبیعی را بر عهده دارد.
